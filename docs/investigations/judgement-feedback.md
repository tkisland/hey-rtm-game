# ノーツ通過時のカクつきの調査

押さなくてもノーツが終端に達するとカクついて見えるという報告を受け、MISS表示の更新を調べました。実機のフレーム落ちは未再現ですが、通過時に増える処理は確認できました。

## 確認と変更

従来のshowHitは、MISSも成功判定と同じように表示を拡大するWeb Animationを作り、同じMISS文字・判定属性・空の誤差欄を書き直していました。スコアが変化していなくても、通過したノーツの分だけ数値書式を実行していました。

MISSの文字・色・最終判定から800msの表示・集計は保ち、MISSの拡大アニメーションを省きます。同じ表示内容は書き直さず、スコア・コンボ・最大コンボも値が変わった場合だけ書式化・更新します。初期表示の書式化は読み込み時に済ませ、最初の判定へ持ち越しません。成功時の拡大・発光・火花、ノーツの移動時刻・判定窓・入力補正は変更しません。

## 比較

[測定値](judgement-feedback-profile.json)は390×844・DPR3（Canvas上限2）・Chromium・CPU4倍遅延、6レーン×20組の120ノーツを押さずに通過させた3.6秒の単発比較です。YouTubeはテスト用APIで、実機や本物の動画のデコード負荷は再現していません。

| 項目 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 判定文字のアニメーション生成 | 120 | 0 |
| Layout回数 | 24 | 6 |
| UpdateLayoutTree回数 | 86 | 6 |
| FunctionCall最長 | 30.387ms | 14.546ms |

これは通過時の不要な処理を減らせたという結果で、実機の症状の原因確定や、同じ改善率を保証するものではありません。映像時刻の更新停滞など、ほかの要因も残ります。

測定を繰り返す場合は管理者用devサーバーを起動し、次を実行します。末尾のトレース保存先は省略できます。ブラウザ・テスト用ページはスクリプトが終了時に閉じ、サーバーは別途終了してください。

```sh
npm run dev:admin -- --port 4190 --strictPort
# 別ターミナルで実行
node scripts/profile-judgement.mjs http://127.0.0.1:4190 /tmp/judgement-trace.json
```

ブラウザ回帰テストでは、押さずに100ノーツを通過させ、同じMISS文字と0点を繰り返し書き換えないこと、別レーンで接近中のノーツが毎フレーム進むこと、判定表示の消失時間・最終MISS件数・結果の点数を確認します。成功時と長オシの演出は既存テストで確認します。
