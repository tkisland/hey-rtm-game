# 押下時のフィードバックの軽量化

## 対象

Android（Galaxy Z Fold、折りたたみ状態のChrome）でのプレイ途中の遅れと、押下時に一瞬重く感じるという報告を受け、共通の入力処理を調査した。実機の症状・原因は未確定。以下はホストのChromiumで確認できた処理削減であり、端末固有の同期ずれを解消したという結果ではない。

## 変更

- 成功判定のポップは同じキーフレームを使うため、毎回キャンセル・新規作成していたAnimationをレーンごとに再利用する。最大6個。連打でも先頭から再生し、MISS・リセット時にはキャンセルする。判定文字・誤差・800msの表示期限は維持する。
- pointermoveのたびに6ボタンのgetBoundingClientRectを呼んでいた処理を、ジェスチャー中のスナップショットに置き換える。押下状態のスタイル変更後に位置を読み直し、同期レイアウトを繰り返す経路を減らす。新しい指の押下、ウィンドウ／visual viewportのリサイズ・スクロール、ボタンのリサイズ時には無効化する。入力イベントを解除する際にObserverも破棄する。

判定・スコア・動画時計・効果音・火花の仕様は変更しない。

## 計測

`node scripts/profile-hit-feedback.mjs http://127.0.0.1:4190 /tmp/hit-trace.json`

管理者用Viteを4190番で起動する。画面344×882、DPR3（描画上限2）、CPU 4倍スロットリング。YouTube APIはモック、Web Audioは実装を使用。120入力（3キーずつ40組、100ms間隔）を処理する同一シナリオを修正前後で1回ずつ測定した。数値はホストの実行状況に左右されるので、改善率の保証や実機FPSの代用にはしない。

| 指標 | 修正前 | Animation再利用後 |
| --- | ---: | ---: |
| 判定Animationの生成数 | 120 | 6 |
| 3入力＋解除の同期処理の中央値 | 7.2ms | 5.6ms |
| 同・最大 | 22.8ms | 20.1ms |
| トレース内FunctionCallの合計 | 920.5ms | 786.7ms |

計測の生データは `hit-feedback-profile.json`。この比較はAnimation再利用までを対象とし、後から追加した位置キャッシュの効果は含まない。入力は実時間で進むため判定誤差は変動し、得点差は性能の指標にしていない。

位置キャッシュはブラウザ回帰テストで、24回のpointermove中のボタン位置読取が合計6回になること、リサイズ通知後は再取得し、新しいジェスチャーでも再取得することを確認する（従来の処理では24×6＝144回）。連続24ノーツの得点、Animation生成上限、リセット後の再利用も検証する。
