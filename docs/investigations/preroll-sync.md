# 冒頭広告後にノーツが先行する現象の調査

対象は、ノーツ位置を調整済みでも、冒頭にYouTube広告が入った回だけノーツが少し早く感じられるという報告です。実際の広告・実機のログは未取得で、原因はまだ確定していません。

## 確認できたこと

- ゲーム時刻はYouTubeの`getCurrentTime()`を短く補間して使用します。広告時間を独自に加算する処理はありません。
- 保存したノーツ位置補正はページ開始時に読み込み、調整画面で保存したときだけ変更します。広告や再生状態の切り替えでは書き換えません。
- 「広告時刻から本編0秒へ戻る」「広告中はAPI時刻が0秒のまま」「状態通知なしで300msだけ戻る」の3種類を、連続・250ms・750ms間隔の本編時刻更新で組み合わせ、9種類の仮想APIパターンをテストしました。本編の最初のノーツ（7.65秒）以降に50msを超える内部時計の先行が残る挙動は再現していません。これは実際のYouTube広告がこの通り動くという証拠ではありません。
- 利用する[公開IFrame API](https://developers.google.com/youtube/iframe_api_reference)には広告開始・終了専用の通知がなく、広告終了の時点を確実に判定できません。動画長や動画URLも広告を確実に識別する指標とは限りません。
- APIの時刻と、実際に端末から見える映像・聞こえる音の時刻は別です。広告から本編へ移る際の出力遅延が候補に残りますが、現在の情報から断定できません。

## 再現時に記録する手順

診断改善を公開した後、`game.html?sync=1`を開き、保存済みの補正値を変えずに比較します。

1. 冒頭広告が終わったら、同期診断の「広告が終わった」を押します。
2. 早く感じたら「ずれを感じた」を押します。
3. 同期診断を折りたたみ、ゲームの「最初からやり直す」を押し、同じ曲の同じ箇所で先行が残るか確認します。リスタート要求の時点は自動記録します。
4. 同期診断を開き、同じページの「診断ログを保存」でJSONを保存します。端末・ブラウザと、やり直しで戻ったかどうかを添えて比較します。

診断パネルは折りたたんでも記録が続きます。全画面が見づらい場合は、印をつけるときと保存するときに開いてください。

## 記録の改善

- 直近480件に加え、最初にPLAYINGとなった時点から60秒の記録（最大256件・直前の少量の記録を含む）を保存します。ページを開いてから再生するまで時間が空いても、再生開始が記録の基点になります。
- 状態・動画長・動画ID・時刻の後退・シーク・再同期などの変化を、直近128件の別履歴へ残します。
- APIが返す動画長・読込率・動画IDを補足します。これらから自動的に「広告中」とは判定しません。取得失敗はnullにし、ゲームを停止しません。
- 広告終了・ずれを感じた時点・リスタート要求を最大64件記録します。手動の印は利用者の観測であり、YouTubeからの広告通知ではありません。
- メタデータを読むのは`?sync=1`のときだけで、通常250ms間隔です。診断内容は端末内のJSONへ保存し、自動送信しません。

## 切り分け

- 広告後も「補間 − API」が大きく残る場合は、内部の補間・再同期を調べます。
- 内部の差が通常範囲で補正値も変わらないのに体感だけ先行し、やり直すと戻る場合は、再生セッションごとの映像・音声出力の差を追加確認します。出力遅延はAPIログだけでは測れません。
- 動画長やAPI時刻の切り替えと、内部の再同期・手動で付けた印を比較します。APIに見える変化がなくても、広告がなかったとは断定しません。

今回の変更は調査用の記録強化です。再生時計・判定・譜面・補正値の計算は変更しません。実広告での原因確定や解消は未確認です。
