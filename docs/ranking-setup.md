# さくらで簡易ランキングを使う

公開先は https://hey.jpn.org/rhythm/ です。プレーヤーのログインは不要で、リザルトから半角英数字3〜6文字の名前を毎回入力して登録します。小文字は大文字に統一し、同じ名前でも別のプレイ記録です。曲・難易度・譜面内容ごとに上位20件を表示します。

## 必要なもの

- さくらのレンタルサーバー・スタンダードのMySQL。
- PHP 8.2以上、PDO MySQL、HTTPSへのサーバー側通信（`allow_url_fopen`）。PHP 8.3・MySQL 8.4で検証しています。
- FTPで、ドメインの公開フォルダーに加え、アカウントのホームフォルダーへファイルを配置できること。

Node.js・Docker・SSHのサーバーへの導入は不要です。Dockerは開発／CIの検証でのみ使用します。FirebaseのルールやプレーヤーのGoogleログインを追加する必要はありません。既存の管理者ログイン・譜面保存はFirebaseを継続使用します。

## 1. MySQLのデータベースを作る

1. さくらのサーバーコントロールパネルで「データベース」を開きます。
2. ランキング用のデータベースを作成し、DBのパスワードを設定します。
3. **データベースサーバー名・データベース名・ユーザー名・パスワード**を控えます。ホストは通常 `mysqlXXX.db.sakura.ne.jp` のような専用名です。`localhost`やFTPのサーバー名に置き換えないでください。
4. PHPの利用バージョンとPDO MySQLが有効なことを確認します。PHPの切り替えが必要な場合、同じドメインの既存サイトも動作を確認してください。

DBのパスワードをチャットやGitHubに貼る必要はありません。

## 2. テーブルを作る

1. PRをマージし、GitHub Actionsの成功した実行から **`rhythm-site` と `ranking-setup` の2つ**をダウンロードして展開します。
2. さくらのコントロールパネルからphpMyAdminへ入り、作成したデータベースを選びます。
3. 「インポート」で `ranking-setup` 内の **`schema.sql`** を選び、実行します。
4. `rhythm_schema`、`rhythm_boards`、`rhythm_sessions`、`rhythm_entries`、`rhythm_rate_limits` の5テーブルがあることを確認します。

SQLは初回セットアップ用です。既存テーブルを削除する命令は含みません。通常のFTP更新のたびにインポートする必要はありません。

## 3. 接続設定を公開フォルダーの外へ置く

1. FTPで、`www`フォルダーが見えるアカウントのホーム位置を開きます。
2. **`www`と同じ階層**に `rhythm-private` フォルダーを作ります。`www`やドメインの公開フォルダーの中には作りません。
3. `ranking-setup` の `config.example.php` をPCでコピーして **`config.php`** という名前にします。
4. ファイル内の `db_host`・`db_name`・`db_user`・`db_password` を、手順1の値に変更してUTF-8（BOMなし）で保存します。`allowed_origin` は `https://hey.jpn.org` のままにします。
5. 編集した `config.php` を `rhythm-private` へFTP転送します。公開用ZIPやリポジトリには入れません。

```text
/home/さくらのアカウント名/
├─ rhythm-private/
│  └─ config.php                 ← DB接続設定。公開しない
└─ www/
   └─ …ドメインの公開フォルダー…/
      └─ rhythm/
         ├─ index.html
         ├─ game.html
         ├─ rankings.html
         ├─ assets/
         └─ api/
            ├─ ranking.php
            ├─ core.php
            └─ catalog.json
```

`www`自体がドメインの公開フォルダーなら、中間のドメインフォルダーは不要です。APIはさくらの `/home/アカウント名/rhythm-private/config.php` を自動で探します。独自構成で見つからない場合は、`rhythm/api/`専用の `.htaccess` に `SetEnv RHYTHM_CONFIG_PATH /home/アカウント名/rhythm-private/config.php` を設定できます。既存サイトのルート設定は上書きしません。設定ファイルが公開フォルダー内にある場合、APIは読み込みを拒否します。

## 4. 公開用ファイルをFTP転送する

`rhythm-site` を展開した**中身**を、従来の公開先`rhythm`フォルダーへ転送します。今回は **`api`フォルダーと`rankings.html`も含めます**。`ranking-setup`の中身は公開フォルダーへ転送しません。

順番は `api`・`assets`・画像 → HTMLです。既存のハッシュ付きassetsを一括削除せず、ドメイン直下のサイトや`rhythm-private`には触れません。詳しくは[FTP公開手順](sakura-deployment.md)を参照してください。

## 5. 接続確認と登録

1. https://hey.jpn.org/rhythm/api/ranking.php?action=status を開きます。
2. **`{"ok":true,"enabled":true}`** が表示されれば準備完了です。falseの場合は設定ファイルの位置、DB接続情報、テーブル、PHPバージョンを確認します。PHPソースが表示・ダウンロードされる場合はPHPの実行設定を先に確認します。
3. 選曲画面の「ランキング」から曲・難易度を選び、初期状態で記録がないことを確認します。
4. ページを開き直して通常速度で最後までプレイします。リザルトで英数字3〜6文字を入力し、「登録する」を押します。
5. 名前・点数・最大コンボ・順位が表示され、同じ名前でも次のプレイを別記録として登録できることを確認します。

さくら本番のDBへの接続・FTP送信・本番へのテスト登録は、開発環境からは行っていません。これらは設置後の確認です。

## 登録・順位の仕様

- 合計点（基本スコア＋コンボボーナス＋特殊操作ボーナス） → 最大コンボ → 登録順で並べます。上位20件に加え、登録直後には自分の順位を表示します。
- 1プレイにつき1件。送信後に通信が切れた場合も、同じ内容の再送は同じ記録として扱います。登録成功後は名前の変更や再登録はできません。
- シーク、通常速度以外での再生、ノーツのスキップ、管理者の試遊・下書きは対象外です。音量・補正・ノーツ表示時間の変更、一時停止や読み込み待ちは利用できます。
- プレイ情報の有効期限はページ読込／リスタートから2時間です。開始要求は同一IPから1分あたり30回までです。該当時もゲーム自体は続けられます。
- 名前や記録は公開されます。メールアドレスやプレーヤーアカウントは収集しません。同名の本人確認や、同一人物の記録の統合は行いません。

## 採点ルール3への更新

[採点仕様](scoring.md)に従い、基本100万点＋コンボ・特殊操作ボーナス（ルール2の1.5倍）の合計を登録します。PHPとゲーム側の両方で再計算します。今回の更新ではDB構造・秘密設定・Firebaseルールの変更は不要です。最新の `rhythm-site` 全体をFTPで更新し、特に `api/core.php` と `api/catalog.json` も同じZIPのものへ置き換えてください。更新中の登録を避けるため、作業中は公開フォルダー外の `config.php` を一時的に別名にし、全ファイルの転送後に戻す方法も使えます。

旧ルール1・2の記録はDBに保持しますが、新ルール3のランキングには表示しません。更新前から開いていたページは再読み込みが必要です。古いルールのプレイ途中の記録は新ルールへ登録できません。SQLの再実行・テーブル削除はしないでください。切り戻す場合もHTML・JS・API・カタログを以前のZIPへまとめて戻します。

## 譜面を更新した場合

譜面JSONのSHA-256を版として使い、採点ルールの版も区分に含めます。譜面の内容や採点ルールの版が変われば新しいランキングになり、古い記録はDBに残ります。現在の譜面のランキングは選曲画面から閲覧できます。既存の公開譜面を管理者が更新する場合、PHPファイルやSQLの再設定は不要です。

サーバーはビルド済みの収録譜面、または既存Firebaseの**公開済み**譜面から内容を取得し、プレイ開始時に保存します。ブラウザから任意の譜面JSONを受け付けません。Firebaseを使う場合、従来の `FIREBASE_WEB_CONFIG` を設定して同じZIP内のHTML・JS・`api/catalog.json`を一緒に更新します。

登録時は判定結果の件数・ノーツID・重複・判定値を確認し、同時オシの片方がMISSならその組は0点、長オシ等は最終判定で採点する現在のルールをサーバーでも計算します。ブラウザが送る点数・コンボと一致しない結果は拒否します。最低プレイ時間や重複送信も確認します。

これは簡易ランキングです。ブラウザでの自動操作や判定結果の偽造を完全に防ぐものではなく、競技用途の厳密な不正対策は対象外です。

## 保守と切り戻し

公開したZIP・コミット番号と、phpMyAdminからのDBエクスポートを保管します。通常の静的ファイル更新・切り戻しではDBを消しません。登録を停止する場合は、公開フォルダー外の `config.php` を一時的に別名へ変更すると「準備中」になり、ゲームは引き続き遊べます。

期限切れのプレイ情報と古いレート制限情報は開始要求時に少しずつ削除します。ランキング記録は自動削除しません。不適切な記録を削除する場合は、バックアップ後、phpMyAdminで `rhythm_entries` の該当IDだけを削除します。

## 開発時の検証

```sh
npm test
npm run build
npm run test:ranking
```

`test:ranking` はDockerを使い、隔離したPHP 8.3とMySQL 8.4へ実際にテーブルを作成してAPI・ブラウザ操作を検証します。テスト終了時に専用コンテナー・ネットワークを削除します。4194ポートを空けてください。ブラウザ時計の早送りに合わせ、**テストDBの既知の譜面行だけ**最低時間を0にしています。本番APIには時間検証を無効化する機能を設けていません。
