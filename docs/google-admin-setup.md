# Googleログインで譜面を編集・公開する

一般プレーヤーはログイン不要です。管理者は公開サイトの「管理者ログイン」からGoogleアカウントでログインし、譜面の編集・下書き保存・公開を行います。WindowsにNode.jsを入れたり、コマンドを実行する必要はありません。

最初の接続設定だけ、FirebaseとGitHubの画面で行います。このゲーム専用のFirebaseプロジェクトを使用してください。

## 1. Firebaseプロジェクトを作成する

1. [Firebaseコンソール](https://console.firebase.google.com/)を開き、管理するGoogleアカウントでログインします。
2. 「プロジェクトを作成」を選び、名前を入力します。Google Analyticsは今回の機能には不要です。
3. 作成後のプロジェクト概要で「Web（</>）」からアプリを登録します。Firebase Hostingの設定は不要です。公開サイトはさくらのレンタルサーバーの https://hey.jpn.org/rhythm/ を使用します。
4. 表示された`firebaseConfig`を控えます。使用するのは`apiKey`・`authDomain`・`projectId`・`appId`です。これらはブラウザへ配信するWebアプリ用の公開設定です。Googleのパスワードやサービスアカウントの秘密鍵は使用しません。

## 2. Googleログインを有効にする

1. Firebaseの「構築 → Authentication」で利用を開始します。
2. 「ログイン方法」で「Google」を有効にし、サポートメールを選んで保存します。
3. Authenticationの「設定 → 承認済みドメイン」に`hey.jpn.org`を追加します。`https://`や`/rhythm/`は付けません。

## 3. データベースと権限ルールを設定する

1. 「構築 → Firestore Database」でデータベースを作成します。**Standardエディション・デフォルトのデータベース・本番環境モード**を選びます。配置場所は利用者に近い地域を選んでください。
2. Firestoreの「ルール」を開きます。
3. リポジトリの[firestore.rules](../firestore.rules)を開き、「Raw」から内容全文をコピーします。
4. Firestoreのルール欄をその内容へ置き換え、「公開」を押します。この操作は権限ルールの反映で、ゲーム譜面の公開とは別です。

このルールでは、一般プレーヤーは公開済み譜面の取得だけが可能です。下書きの閲覧・保存・公開は登録された管理者に限定し、Webアプリから管理者を追加する操作も拒否します。

## 4. Webアプリの設定をGitHubへ登録する

1. GitHubのリポジトリで「Settings → Secrets and variables → Actions → Variables」を開きます。
2. 「New repository variable」を押し、名前を`FIREBASE_WEB_CONFIG`にします。
3. 値には手順1の設定を、次のJSON形式で入力します。項目名もダブルクォートで囲みます。

```json
{
  "apiKey": "Firebaseに表示されたapiKey",
  "authDomain": "your-project.firebaseapp.com",
  "projectId": "your-project",
  "appId": "Firebaseに表示されたappId"
}
```

4. 保存して、変更を`main`にマージするか「Actions → Build site for Sakura FTP → Run workflow」でビルドします。成功した実行のArtifactsから`rhythm-site`をダウンロードし、[FTP公開手順](sakura-deployment.md)に従って展開した中身をアップロードします。マージ・ビルドだけでは公開サイトは更新されません。

設定のJSON化や登録をCodexへ依頼する場合は、Webアプリの`firebaseConfig`を伝えてください。秘密鍵やGoogleのパスワードは送らないでください。

## 5. 最初の管理者を登録する

1. サイトの「管理者ログイン」から、自分のGoogleアカウントでログインします。
2. 初回はまだ権限がないため、「編集権限がありません」と**アカウントID**が表示されます。このIDをコピーします。
3. Firebaseの「Firestore Database → データ」でコレクション`admins`を作成します。
4. ドキュメントIDにコピーしたアカウントIDを指定します。「自動ID」は使用しません。
5. フィールド`enabled`を追加し、型を**boolean**、値を**true**にして保存します。
6. サイトの管理者画面を開き直します。管理者としてエディターを使えるようになります。

Googleでログインできることと、譜面を編集できることは別です。他のGoogleアカウントは、同じ手順で管理者として登録しない限り編集できません。管理者を無効にする場合は、そのドキュメントの`enabled`を`false`にします。

## 通常の編集・公開

1. サイトの「管理者ログイン」からGoogleでログインします。
2. 曲を選び、打ち込み・MIDI/JSON読込・クオンタイズ・微調整で編集します。
3. 「下書きを保存」を押すとオンラインへ保存します。この時点では一般プレーヤーの譜面は変わりません。
4. 「譜面の再生確認」または「保存してゲームで試す」で確認します。下書きの試遊も管理者限定です。
5. 「公開する」を押し、対象曲とノーツ数を確認して確定します。次にゲームを開くプレーヤーから新しい譜面を使用します。譜面更新のたびにGitHubを操作する必要はありません。

編集途中の変更は「下書きを保存」するまでオンラインに保存されません。保存・公開に失敗した場合は変更を保持して通知します。必要ならエディターのJSON書き出しでバックアップしてください。他の管理者による保存と競合した場合は上書きせず通知します。

以前のブラウザ下書きは自動でオンラインへ送信しません。以前に書き出したJSONを管理者画面で読み込んで保存できます。現在は登録済み楽曲の譜面が対象です。曲カタログへの追加はリポジトリで行います。

## 接続状態の見方

- 「管理者ログインは準備中」：Webアプリの設定がまだ公開ビルドへ反映されていません。GitHubの変数と再公開を確認します。
- 「編集権限がありません」：ログインしたアカウントのIDと`admins`のドキュメントID、`enabled`がbooleanのtrueであることを確認します。
- 「ログイン用ドメインが未登録」：Authenticationの承認済みドメインへ`hey.jpn.org`を登録します。
- Googleの画面を開けない：ブラウザのポップアップ制限や、Googleのログイン用通信が許可されているかを確認します。

実際のGoogleログイン、設定した公開サイトからの保存・公開、別の未登録アカウントによる拒否は、初回設定後に確認してください。
