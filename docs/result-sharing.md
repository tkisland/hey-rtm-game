# 結果IDによるX共有と画像キャッシュ

リザルトの「Xで共有」は次の順に改行します。投稿は利用者が確認して行います。

```text
#HeyRhythm
得点率に応じたメッセージ
曲名 / 難易度
SCORE：1,100,000
MAX COMBO：508
https://hey.jpn.org/rhythm/share.php?id=…
```

通常速度で完走した結果は、再生開始時に発行したトークンと全ノーツの最終判定を `api/ranking.php?action=share` へ送ります。サーバーが判定・経過時間・得点・最大コンボを確認し、推測しにくい32桁の結果IDを発行します。名前の入力・ランキング登録・プレーヤーのログインは不要です。同じプレイを再送しても同じIDを返し、共有とランキング登録で違う判定内容を確定させることはできません。

結果IDの情報はDBの `rhythm_shared_results` に保存します。URLのscore・comboなどを変更しても画像の値は変わりません。URLには登録トークン・名前・判定配列を含みません。IDを知っている人は共有ページを閲覧できます。ブラウザの判定内容そのものは自己申告なので、人が遊んだ証明ではなく、サーバーで整合性を確認した結果です。

## 本番反映：さくらのレンタルサーバー

1. GitHub Actionsの `ranking-setup` から **`002-share-results.sql`** を取得します。
2. さくらの管理画面から、ランキングで使用中のDBをphpMyAdminで開きます。そのDBを選択し、SQLタブまたはインポートから同ファイルを実行します。追加するのは新しいテーブル1個です。既存テーブル・記録・スキーマ番号1は保持します。再実行しても既存データは消えません。
3. 同じビルドの `rhythm-site` 全体を `https://hey.jpn.org/rhythm/` へFTP更新します。特に `share.php`・`share-image.php`・`share-common.php`・**`share-cache.php`**、`api/core.php`・`api/ranking.php`・`api/catalog.json`、HTML・JS・CSSをまとめて更新してください。背景PNG・フォント・OFLライセンスも `share/` に必要です。
4. ページを再読み込みして1曲プレイします。リザルトの共有画像の準備が終わった後、X共有のURLが `share.php?id=32桁` になり、そのURLを開くと曲名・TOTAL・MAX COMBOの画像が出ることを確認します。ランキングへ名前を登録する必要はありません。
5. 公開フォルダ外の既存 `rhythm-private` に、PHPが `share-cache` フォルダを作成します。作成できない場合はFTPで同フォルダを作り、PHPの実行ユーザー（通常は契約アカウント）へ所有者の読み書き権限を付けてください。生成画像を `www` や `rhythm/` へアップロードする必要はありません。

例：既存設定が `/home/ACCOUNT/rhythm-private/config.php` なら、キャッシュは `/home/ACCOUNT/rhythm-private/share-cache/` です。追加APIキー・Firebaseルール変更・DBパスワード変更は不要です。既存のconfig.phpをサンプルで上書きしないでください。

SQLが未実行でも従来のランキングは動きますが、画像付き共有は準備中となります。切り戻す際はサイト一式を以前のビルドへ戻し、追加テーブルと記録は残します。削除・初期化のSQLは不要です。

## 画像の保存と制限

- 画像はPHPのGDとFreeTypeで1200×630のPNGとして生成します。曲名・メッセージ・TOTAL・MAX COMBOを描き、基本スコアは描きません。フォントはDela Gothic Oneで、`share/OFL.txt` を同梱します。
- 共有IDを返す前に画像を作成し、以後は同じPNGを返します。画像版は4です。同時生成をロックで防ぎ、保存時は一時ファイルから置き換えます。共有ページはJavaScriptなしでOGPメタタグを返します。
- **新規生成はサイト全体で1分30回まで**が初期値です。キャッシュ済み画像の取得はこの制限を消費しません。存在しないID・以前の数値URLではGDを動かしません。
- **PNGキャッシュの合計上限は128MiB**です。上限を超える場合は古い画像から整理し、新規生成時には作成後30日を過ぎた画像も整理します。専用cronは不要です。
- 画像を整理してもDBの結果IDは保持します。以前のリンクが開かれた場合は制限内で再生成します。HTTPのContent-Length・ETag・304応答と最大24時間のキャッシュ指定にも対応します。
- 上限に達した場合や生成に失敗した場合は、数値を受け取って再生成を繰り返すのではなくエラーを返します。リザルトでは曲ページの共通OGPで文章を共有でき、「画像付き共有を再試行」から同じ結果IDの準備をやり直せます。

必要なら、公開フォルダ外の既存config.phpへ次の任意設定を追加できます。単位はバイトです。

```php
'share_generations_per_minute' => 30, // 1〜300
'share_cache_max_bytes' => 134217728, // 1MiB〜1GiB
```

## シーク・通信不調・以前のリンク

シークや再生速度の変更があるプレイ、サーバーへ接続できない場合もX投稿文を作れます。その場合のURLは曲ページで、共通OGPを使います。シーク数の注記はメッセージ行に含めます。見本プレイ・管理者プレビューは共有対象外です。

以前の `share.php?song=…&score=…` は、曲への案内と共通OGPを表示します。数値パラメータから結果画像や得点表示を作る処理は廃止しています。以前の画像URL `share-image.php?song=…` にも共通OGPを返します。X側に保存済みの古いカードをこちらから強制更新することはできません。

共通OGPは `ogp-v2.png` です。`ogp-test-v1.png` にも同じ版表記なしの画像を置き、以前のURLとの互換性を保っています。Xの画像取得・キャッシュ更新はX側の状況にも依存します。
