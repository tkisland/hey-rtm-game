# ランキング・共有の改善手順

## 第1段階（この変更）

- コンボ・最大コンボ・コンボボーナスを譜面の採点順で計算する。通常ノーツは始点、長オシ／オシ変は終点、同時刻はID順。途中失敗も終点へ配置する。
- ブラウザ・PHPで同じ規則を使用し、送信配列の並べ替えで点数を変えられないようにする。
- 採点ルール7へ更新する。旧ルール1〜6の記録は保持し、現行ランキングから分離する。
- 登録トークンは再生開始を確認してから発行する。ページを開いた時点では発行しない。一時停止・再開は同じトークンを使う。
- 「↻」「もういちど遊ぶ」と、終了後に動画内で先頭から再生した場合は新しいプレイとして扱う。終了イベントで時刻だけが戻った場合はリセットしない。
- ボードが見つからないトークンには、採点ルール変更と区別したエラーを返す。

最新のサイト一式（HTML・JS・PHP・api/catalog.json）を同じビルドからFTP更新する。SQL・Firebaseルールの変更や記録削除は不要。更新前のページは再読み込みする。

最終判定自体はブラウザの自己申告であり、再生開始時のトークンでも実プレイは証明できない。この段階で対処するのは、配列順による水増しと、再生しない閲覧に伴う不要な書き込みである。

## 第2段階（実装）：共有結果IDと画像キャッシュ

- 名前のランキング登録と独立して、サーバーで整合性を確認した結果IDを発行して共有する。
- URLの数値から画像を作る方式を置き換える。実プレイを証明する機能とは区別する。
- 結果ID・画像版ごとに生成画像を再利用する。同時生成を防ぎ、未生成画像の生成回数と保存容量にも上限を設ける。
- 以前の数値URLは共通OGPへ切り替え、結果ID付き画像は公開フォルダ外で再利用する。生成回数・容量・同時生成を制限する。
- 本番では追加SQL `server/setup/002-share-results.sql` の実行が必要。手順・制限・保存先・復旧方法は [result-sharing.md](result-sharing.md) を参照。

## 続く段階

- 管理者が理由を残してランキング記録を非表示・復元できる仕組み。
- 共有回線を考慮した設定可能な制限、独立したハッシュ鍵、信頼するプロキシの明示。
- ノーツIDの上限統一、配布物からmanifestの除外、CSPの報告専用設定と互換性検証。
- 本番Firebaseへ適用済みのルールをリポジトリのfirestore.rulesと照合する。ルールファイル・エミュレーターテストはリポジトリに存在する。

ogp-test-v1.pngは以前の画像URLへ新しい画像を返すための互換ファイルであり、単純には削除しない。
