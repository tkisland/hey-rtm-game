# HEY! RHYTHM!

Hey!Mommy!の公式YouTube MVと同期する、非公式ファンメイドの6レーンリズムゲーム・プロトタイプです。一般プレーヤーはトップページで曲を選び、管理者が公開した収録譜面で遊びます。管理者はGoogleログイン後のブラウザ画面で譜面を編集・保存・公開できます。現在の収録曲は「SUPER MOMMY GIRLS」の1曲です。Vite + Vanilla TypeScript + Canvasで実装し、一般プレーヤーはログイン不要です。管理者向けのオンライン機能にはFirebase AuthenticationとFirestoreを使用します。Firebase未設定でも収録譜面で遊べます。

動画ID：`pJDfWpZ7CI4` / [公式MV](https://www.youtube.com/watch?v=pJDfWpZ7CI4)

**初期表示は、提供されたMIDIから変換した収録譜面「SMG002」です。** 一般向けの画面には編集・下書き・仮譜面の切り替えを表示しません。オンラインの公開譜面があれば、そちらを優先して使用します。仮譜面と旧ブラウザ下書きの切り替えはローカル制作ツールで利用できます。オンラインでは管理者の下書きを保存し、明示的に公開するまで一般プレーヤーへ配信しません。仮譜面のBPM140は楽曲解析の結果ではありません。 音声・映像のダウンロード、抽出、複製は行いません。

## ローカル起動

Node.js 24.12以上（クラウドでは24.19.0）、npmが必要です。

```sh
cd /workspace/hey-rtm-game # ローカルではクローンしたディレクトリへ移動
npm ci
npm run dev
```

ターミナルに表示される開発サーバーをPCブラウザで開き、曲の「プレイ」を選んでから、動画の上の**「音を準備して再生・再開」**を押します。収録譜面の最初のノーツは動画の7.65秒地点です。自動再生は前提にしていません。PCでは動画を再生・再開すると、プレーヤーにフォーカスがある場合はゲームへ入力先を戻します。S / D / F / J / K / Lで入力してください。動画の別の操作後に反応しない場合はゲーム領域を一度クリックしてください（YouTube iframe内のキーはゲームに届きません）。YouTube側のキーボードショートカットは無効にしています。下部の6ボタンでも入力できます。ボタンは横一列で、左からピンク・黄緑・白・赤・紫・黄色です。ノーツとレーンの発光も同じ色にしています。スマートフォンを同一ネットワーク上の開発サーバーに接続する場合もHTTPで開いてください。

ゲーム画面を開いたときは動画の0秒から再生します。譜面の7.65秒という開始時刻は動画の開始位置とは分けて扱い、勝手に5.15秒へシークしません。「音を準備して再生・再開」でタップ音の出力も準備します。YouTube内で再生を始めた場合は、再生中も押せる「タップ音を準備」から音声を有効にできます。この操作では動画を再生・シークし直しません。通常の再開は一時停止した位置から、「最初からやり直す」は譜面とスコアを初期化して動画の0秒へ戻ります。iPhone等で再生が始まらない場合は、プレーヤー内の再生ボタンを押してください。一時停止・バッファリング中は入力判定を停止し、スコアを保持します。

## ビルド・静的Webサーバーへの設置

```sh
npm run build
npm run preview
```

`dist/` 内の **index.html・game.html・admin.html・assets/・.vite/をまとめて** 既存サーバーへアップロードしてください。`editor.html`という単独のローカル編集ページは出力しません。オンラインの編集UIは管理者の本人確認・権限確認後に読み込みます。権限の強制はFirestoreのサーバー側ルールで行います。`scripts/check-public-build.mjs`は一般向けページの初期読込に編集UIが混入していないこと、編集UIが管理者画面へ遅延ロードされること、旧編集ページ・未参照ファイル・テスト用設定の混入がないことを検査します。

配信ディレクトリは継ぎ足しではなく成果物全体で置き換えます。GitHub Pagesのワークフローは`dist/`全体を配信します。`base: './'`のためサブディレクトリにも設置でき、URL末尾を`/`としてHTTPSで配信します。Node.jsは公開先に不要です。

- `file://` でHTMLを開かず、HTTP(S)サーバーを使用してください。
- IFrame APIの`origin`は実際の`location.origin`を設定します。Refererを遮断する`no-referrer` / `same-origin`ヘッダーを設定しないでください。HTMLとiframeは`strict-origin-when-cross-origin`を使用しますが、公開サーバーやブラウザ拡張の設定も確認してください。
- CSPを設定する場合、YouTube APIスクリプトの`www.youtube.com`、`s.ytimg.com`、iframeの`www.youtube.com`を許可してください。MVの通信には`i.ytimg.com`と`*.googlevideo.com`も使用されます。必要なローカルのスクリプト・CSSも許可してください。
- YouTube標準のプレーヤーのクリック・タッチ操作を維持します。`disablekb: 1`でプレーヤー側のキーボードショートカットを無効にし、Fでの全画面化やJ/K/Lでの動画操作を防ぎます。動画の上にゲームUIを重ねません。プレーヤーの高さは最低200pxです。
- 埋め込み拒否・通信障害・Referer不足（153等）は画面に表示し、ゲームを停止します。公式動画へのリンクも常に表示します。

## GitHub Pagesでの公開

公開URLは https://tkisland.github.io/hey-rtm-game/ です。

**リポジトリ直下の開発用`index.html`をそのまま配信すると、TypeScriptを実行できず、CSS・Canvas・YouTubeも読み込まれません。公開にはビルド済みの`dist/`を使います。**

`.github/workflows/deploy-pages.yml`が、`main`へのpush時に`npm ci` → `npm test` → `npm run build`を実行し、`dist/`だけをGitHub Pagesへデプロイします。PRではテスト・ビルドを実行し、公開は行いません。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します（「Deploy from a branch」でリポジトリ直下を配信しないでください）。
2. 公開ワークフローを含む変更を`main`へマージします。
3. **Actions → Build and deploy GitHub Pages** の`build`・`deploy`が成功したら、公開URLを再読み込みします。手動の再公開は同ワークフローの **Run workflow** から行えます。

UIがプレーンな文字だけでYouTubeも空欄の場合、配信HTMLに`/src/…ts`が残っていないか確認してください。正しい公開HTMLは`./assets/…js`と`./assets/…css`を読み込みます。CSS・JSの両方がHTTP 200で取得できることを確認し、古いページが残る場合はキャッシュを消して再読み込みしてください。

## 選曲メニューと曲の追加

選曲画面の「遊び方」で、流れるノーツに合わせてタップ・同時押し・長押しを3ステップで実際にプレイできます。各ステップは90 BPM・4拍のカウント付きで約8秒。本番と同じ描画・判定・コンボ・効果音を使い、リズム音に合わせて練習します。スマホの2本指とPCのS D F / J K Lキーに対応し、保存済みの入力補正を適用します。結果を見て「もう一度」で再挑戦でき、音のON/OFF、途中で閉じる・次へ進む操作も可能です。動画や楽曲は読み込まず、設定や譜面を変更しません。画面を離れると中断し、最初から再開できます。

公開URLのトップが選曲画面です。曲名・アーティスト名で検索し、「プレイ」から収録譜面で遊べます。選曲画面ではYouTubeを読み込みません。公開する譜面がない曲は「準備中」とし、仮譜面では開始しません。

一般向けの設定には音量・入力補正・ノーツの見え方などのプレイ設定だけを表示します。編集リンク、下書き・テスト譜面の選択、仮BPM・譜面開始時刻、デバッグ表示は管理者のローカル環境専用です。`?chart=custom`・`?chart=test`の古いリンクは公開済みの収録譜面へ移行し、ブラウザ内の下書きは読み書きしません。`/editor.html`への直接アクセスも公開サイトでは404になります。URLやlocalStorageへ管理者フラグを設定しても保存・公開の権限は得られません。管理者はフッターの「管理者ログイン」から入ります。

管理者のローカル環境では、曲ごとの「譜面を編集」「保存譜面で遊ぶ」「テスト譜面で遊ぶ」と、ゲームの譜面切り替えを利用できます。ゲーム・エディターの「選曲」で戻れます。登録のない曲IDは選曲画面へ戻し、別の曲を誤って再生しません。

曲を増やす場合は、`src/songs.ts`の`SONGS`に次の形式の情報を追加して再ビルドします。公式MVの動画IDと曲名に合わせて値を設定してください。登録後はメニュー・ゲーム・エディター・公式リンクに自動で反映されます。

```ts
export const SONGS: readonly Song[] = [
  DEFAULT_SONG,
  { id: 'new-song-id', title: '曲名', artist: 'Hey!Mommy!', videoId: '公式MVの動画ID', bpm: 140, startTime: 12 },
];
```

`id`は重複しない固定の識別子にしてください。変更すると以前の編集内容と保存設定を参照できなくなります。`bpm`（80～200）と`startTime`（動画先頭からの秒数）はテスト譜面の初期値です。実際の楽曲に合った譜面はその曲のエディターで作成・JSON読込します。収録譜面は`src/bundled-charts.ts`へ登録し、曲情報の`chartId`に対応するIDを指定すると全利用者へ配信できます。

既存曲の編集・試遊用データは従来の保存キーをそのまま読みます。追加曲は保存キーに曲IDを付けて分離し、他の曲の編集内容を上書きしません。ブラウザのデータ削除や配信元の変更には引き継がれないため、JSONのバックアップを使用してください。

## 収録譜面 SMG002

提供された`game-SMG002.mid`を全509ノーツのまま変換し、選曲画面の主ボタン・ゲームの初期譜面にしています。単押し487個・長押し22個・2レーン同時押し32組です。SMG001から開始時刻・レーンを引き継ぎ、更新MIDIに合わせて長押し17個の終端を変更しています。旧MIDIと変換設定は`charts/source/`に残しています。エディターへ取り込む場合は「収録譜面を読み込む」を使います。既存の編集データは自動で置き換えません。管理者のローカル環境では、テスト譜面とブラウザ保存譜面を「設定 → 管理者用の試遊譜面」で切り替えられます。公開サイトはオンライン公開済み譜面を優先し、まだオンライン公開されていなければ収録譜面を使用します。オンライン取得に失敗した場合はゲーム開始を止め、再読み込みを案内します。

- **MIDIの0秒／0tickを、MVの7.65秒へ配置**します。MIDIに含まれる休符・同時押しの時刻はそのまま残します。以前の音源解析用に示した0.585秒の余白は追加・減算しません。
- MIDI内のテンポイベントを全トラックに適用して、各ノートの始点・終点を動画の秒数へ変換します。開始時点は約166 BPM、動画18.626632844秒から192 BPMです。テンポの変わる位置へノーツをそろえ直す処理は行いません。
- **ノート長が1.5拍以上なら長押し**です。判定には秒数ではなくMIDIのtick差とPPQを使います。テンポ変更をまたぐ長押しは、各区間のテンポで終点まで計算します。1.9625拍のノートも長押しに含みます。
- 最初のノーツは動画7.65秒の黄色、最後の長押しの終点は約214.641秒です。

ユーザー指定の音程割り当て（低音側から左→右）：

| MIDIノート番号 | レーン | キー・色 |
| --- | --- | --- |
| 38 / 39 | 1 | S・ピンク（39の6ノーツもここへ） |
| 40 | 2 | D・黄緑 |
| 41 | 3 | F・白 |
| 43 | 4 | J・赤 |
| 45 | 5 | K・紫 |
| 47 | 6 | L・黄色 |

オクターブの音名表記はDAWによって異なるため、番号で管理します。変換で未割り当ての音や同レーンの同時入力・長押し区間の衝突を検出した場合は、ノーツを捨てずにエラーにします。

再生成には追加パッケージを使わず、Node.jsで次を実行します。

```sh
node scripts/midi-to-chart.mjs charts/source/game-SMG002.mid charts/source/game-SMG002.config.json src/charts/smg002.json
```

生成JSONの`tempoChanges`は、動画先頭からの秒数と以降のBPMです。エディターで読み込んだ場合もJSON保存・Undo/Redo・試遊へ保持し、拍グリッド・スナップ・クオンタイズに反映します。MIDIのテンポ変更が拍の途中にある場合も拍の位相を継続し、変更点を新しい1拍目にしません。エディターのBPM欄は初期BPMです。テンポ変更点を画面から追加・移動するUIはまだありません。

## PCのキーボード入力

YouTube iframe内のキーイベントは配信元が異なるため、ゲーム側のキー処理に届きません。公式プレーヤーの`disablekb`設定で動画のキーボードショートカットを無効にし、PCで再生・再開したときにゲームまたはエディターの入力エリアへフォーカスを戻します。設定入力欄などにあるフォーカスは移しません。フォーカス移動ではスクロールせず、タッチ端末では自動移動しません。動画のクリック・タッチによる再生、一時停止、シーク、全画面ボタンは使用できます。

別の動画操作後にキーが反応しない場合は、ゲーム領域・入力エリアを一度クリックしてください。ブラウザ自体のF11やCtrl/Cmd付きショートカットは通常どおりです。

## 横一列のボタンと判定位置

親指2本で持って遊ぶ際にノーツが指で隠れにくいよう、上に水平な判定ライン、下にピンク・黄緑・白・赤・紫・黄色の6ボタンを配置しています。各レーンの判定位置は同じ高さで、全レーンの上下方向の移動は等速です。同じタイミングのノーツは同じ高さに並び、下にあるノーツから押します。手前で加速する表現は使わず、ノーツ幅とレーンの広がりだけを控えめに変えます（奥の幅は手前の82%）。判定は上側の白い判定ラインが0ms、周囲の帯がPERFECT/GREAT/GOODの範囲です。

薄い横線が4分音符ごとの拍を示し、全レーンをまたいでノーツと同じ速度で流れます。拍の基準から4拍ごとの線は少し明るくしています。譜面の`beatOrigin`（省略時は`startTime`）とテンポ変更を使い、変更が拍の途中でも位相を継続します。入力補正・ノーツ全体の位置はノーツと拍ガイドへ共通に反映します。エディターの入力ボタンと自動プレビューも横一列にそろえ、プレビューにはゲーム用の入力補正を加えません。

ボタンは幅44px以上・縦60〜68pxの領域を持ち、上部のキー表示と下部の丸印を目安に親指で押せます。最速の落下時間1秒でも遅いGOODの端がボタン上端より16px以上上になるよう、判定ラインとボタンを離しています。ボタン下端からゲーム面の下端までは44px空け、ホームインジケーター用のセーフエリアも追加します。操作案内はこの余白内に移し、上のスコア表示をコンパクトにしてノーツの表示範囲を広げています。スマホ縦画面ではゲーム面を最低248px、空きに合わせて最大640pxまで確保します。画面が小さいほど譜面が流れる縦の範囲は短くなります。タップすると下のボタンと上の受け口が同じレーン色に光ります。長押し中はボタンとレーンが光り、帯が終点までつながります。同時押しは実際のノーツを2個なら直線、3個以上なら滑らかな曲線でつなぎます。判定と入力誤差は上の判定ラインの近くに表示し、指で隠れにくくしています。ボタンを押しても位置・大きさを変えません。

スマホでは、Canvas・ボタン・スコアを含む面全体を安定した小ビューポートの高さ（`svh`）で配置します。ボタンだけを別の固定領域に分けず、スクロールやタップで到達位置がずれないようにしています。画面回転には追従し、短い横向き画面ではMVとゲームを左右に配置します。ホームインジケーターの余白も含めます。エディターの自動プレビューも同じ遠近感と横一列の到達位置を使います。

GOOD以上では、ボタンより上の判定ラインから光の輪と上向きの火花が広がります。PERFECT・GREAT・GOODの順に光を強くし、同時押しは各ボタンで独立して表示します。長押しの始点・成功した終点でも表示し、MISSや空打ちでは成功エフェクトを出しません。ボタンや判定位置は動かさず、420msで消えます。端末で動きを抑える設定が有効な場合は、火花や輪の拡大を省いた短い発光に切り替えます。

長押しを保持している間は、始点の演出が消えた後も上の判定ラインから火花が散り続けます。火花の動きは楽曲の時計に合わせ、粒子を蓄積せず一定の本数で描画します。指・キーを離す、終端の判定が確定する、一時停止・バッファリング・シーク時には継続する火花を止めます。エディターの再生確認も同じ演出を使い、端末で動きを抑える設定が有効な場合は静かな発光だけを続けます。

長押しが成立している間は「ジリリ」という金属的な持続音も鳴ります。始点のシンバル音に重ねて、レーンごとに1本のループ音を保持し、指・キーの解除、終端のMISS期限、再生停止・シーク・画面を離れた場合に短くフェードして止めます。同時長押しは独立して鳴り、音量・消音・追加遅延はタップ音の設定と共通です。エディターの再生確認では、プレビューの音量・消音設定を使い、長押し区間を自動で鳴らします。

ゲーム・エディターの操作ボタンでは、連続タップが拡大操作にならないように、タッチ操作の指定に加えてボタンの`touchend`・`dblclick`の既定動作を抑止します。ページ全体を`user-scalable=no`にはせず、ゲーム操作面の外での意図的なピンチ拡大は維持します。

## 設定

ゲーム右上の「設定」で変更し、localStorageに保存します。仮BPM・譜面開始時刻とデバッグ表示は管理者のローカル環境専用です。仮BPM・譜面開始時刻・ノーツ全体の位置は曲ごとに保存し、入力補正・音・落下時間・ノーツの厚さはゲームとエディターで共通です。保存が制限されたブラウザでも、開いているページ内では使用できます。

| 項目 | 初期値 | 範囲・反映 |
| --- | --- | --- |
| ノーツ落下時間 | 2.5秒 | 出現から判定ラインまでの時間。1～4秒、0.25秒刻み。大きくすると早く見える。即時反映。保存済みの値は維持 |
| ノーツの厚さ | 100% | 50～150%、10%刻み。エディターの「ノーツ幅」と共通保存 |
| ノーツ全体の位置 | 0ms | −300～＋300ms、10ms刻み。即時反映 |
| 入力の遅れ補正 | 0ms | −300～＋300ms、5ms刻み。判定・打ち込み・ノーツの到達時刻に即時反映、ボタンは固定 |
| タップ音の追加遅延 | 0ms | 0～300ms、5ms刻み。Web Audioで入力からの追加待ち時間を予約 |
| 仮BPM | 140 | 80～200、整数。次回リスタートで再生成 |
| 譜面開始時刻 | 12秒 | 0～3600秒、0.1秒刻み。次回リスタートで再生成 |
| タップ音 | ON | ボタン・キー入力で短いシンバル風の音。長押し成立中は持続音。OFFも保存されます |
| タップ音量 | 70% | 0～100%、5%刻み。0%は消音。設定を保存 |
| デバッグ | OFF | YouTubeの生時刻、補間後のゲーム時刻、補間状態、プレーヤー状態、適用中BPM、オフセット、FPS、直近の有効入力誤差、最後の判定 |

正のオフセットはノーツの到達・判定を動画時刻より遅らせます。内部では`gameTime = videoTime - offset / 1000`を共通の基準にし、入力補正を引いた`judgeTime`でゲームのノーツと判定を合わせます。BPM・開始時刻の未適用変更は画面に案内します。設定パネルは閉じられます。

「基準音で自動調整」はゲームの設定・エディターの「入力・タップ音のタイミング調整」から開きます。MVと打ち込みを一時停止し、準備の4拍に続く10拍を聞いて、画面のボタンまたはS/D/F/J/K/L・スペースでタップしてください。0.9秒間隔の基準音をWeb Audioの時計で予約し、同じ時計で入力のずれを測ります。1拍に1入力だけを受け付け、孤立したミスタップを除いた8回以上の中央値を5ms刻みの入力補正として提案します。結果を確認して「補正を適用」を押すと保存します。以前の補正には加算せず、測定値で置き換えます。音の追加遅延・既存の譜面は変更しません。

タップ不足、ばらつきが80msを超える結果、±300msの範囲外、画面を離れた場合や音声・画面更新が中断された場合は適用できません。閉じる・やり直す・中断時に予約音を停止します。基準音の音量は測定画面だけの設定で、ゲームのタップ音OFF・音量0でも測定できます。スピーカー・イヤホンを変更した場合は再測定してください。この結果は音声出力と操作を含む補正の目安です。実MVの出力経路と基準音の経路が異なる場合があるため、適用後は実MVで確認し、必要なら入力補正を微調整してください。

入力の遅れ補正は「＋で遅い入力を早い時刻へ補正、−で早い入力を遅い時刻へ補正」です。例えば、0msの設定でいつも判定の表示が＋80msになる場合は＋80msを設定します。内部では`judgeTime = gameTime - inputOffset / 1000`をタップ・長押しの始点/解除・自動MISS/完了・シークのスキップ判定に共通で使用します。遅い入力を補正したのに、その前に自動MISSになることを防ぎます。ボタンの位置は固定したまま、ノーツを補正後の`judgeTime`で描きます。例えば＋80msなら、動画時刻でノーツの80ms後に上側の判定ラインへ到達し、その位置での入力を誤差0msと判定します。判定の帯やボタンを補正値で移動させません。長押しの完了時刻も判定の基準に従います。

「タップ音の追加遅延」は、入力から音を開始するまでの追加待ち時間です。0msが最短で、入力より前に音を出したり、端末・Bluetooth固有の出力遅延を短縮したりする機能ではありません。曲とノーツ全体のずれは「ノーツ全体の位置」、入力判定のずれは「入力の遅れ補正」で調整します。入力から判定までを音の待ち時間で遅らせません。

「タップ音を試す」で鳴り方を確認し、「入力補正・音の遅延を0に戻す」でこの2項目だけを戻せます。タップ音OFFまたは音量0%ではゲーム側の試聴ボタンを無効にします。2項目はゲームとエディターで共通保存します。旧設定に項目がない場合は0msとして読み込みます。デバッグ表示でも補正値・補正後の判定時刻・音の追加遅延を確認できます。

音はWeb Audioの時刻で予約します。初回の音声準備・resumeにかかった時間を追加遅延へ二重に足しません。出力準備が止まっていた場合、設定した追加遅延の予定から80msを超えた古いタップは破棄し、過去の入力音が遅れてまとめて鳴ることを防ぎます。この80msは古い入力の破棄基準で、端末の実際の音声遅延を保証する値ではありません。音のOFF・音量0・遅延変更・一時停止・読込/時刻更新待ち・シーク・リスタート・タブ非表示・破棄では予約した音をキャンセルします。既に鳴っているクリックの終了処理と同時押しの音量制御を維持します。

タップ音は、明るいノイズと金属的な倍音を重ねた240msのシンバル音です。Web Audio APIで端末内に合成します。6レーンのタップ音・長押し音はページ読込後のアイドル時間に1レーンずつ先に計算して共用し、最初の入力で6種類をまとめて生成しません。サンプルは48kHzで作り、出力先のサンプルレートへはブラウザが合わせます。音声バッファはレーンごとに再利用します。外部音源は読み込みません。同時押しの音量をコンプレッサーとソフトリミッターで抑え、長い余韻を残さない構成です。ユーザー入力時に音声を有効化するため、ページを開いただけでは鳴りません。再生停止中や空打ちでも押した音は鳴りますが、ゲームの判定・スコアは変えません。YouTubeの音声・同期処理も変更しません。端末の音量、Safariの音声制約、Bluetooth遅延によって聞こえ方は変わります。

動画の再生開始時から、値0の無音音源をタップ音と同じ出力経路で動かします。再生中は1本だけ維持し、最初のタップや長い休符の後に出力経路を立ち上げる負担を減らします。一時停止・バッファリング・時刻更新待ち・音OFF・音量0・タブ非表示・エラー・破棄で止め、再開時に作り直します。エディターでも、打ち込み用と自動プレビュー用のうち使用中の出力に適用します。実機のスピーカーやBluetoothでの遅延は未計測です。

## 判定と同期

| 判定 | タイミング誤差 | 点数 | コンボ |
| --- | --- | --- | --- |
| PERFECT | ±50ms以内 | 1,000 | 継続 |
| GREAT | ±100ms以内 | 700 | 継続 |
| GOOD | ±160ms以内 | 300 | 継続 |
| MISS | 160ms超で自動判定 | 0 | 解除 |

画面の色付きの帯は、ノーツの**中心**に対する判定範囲です。外側の薄い帯がGOOD（±160ms）、中間がGREAT（±100ms）、内側の濃い帯がPERFECT（±50ms）を示し、各レーンの上側の白い判定ラインが誤差0msの位置です。判定エンジンの`WINDOWS`の境界をノーツと同じ座標変換で描き、画面サイズと落下時間へ追従します。等速のため、早い側と遅い側の縦幅は対称で、全レーンの縦幅もそろいます。ノーツの厚さは判定範囲を変えません。最速の落下時間1秒でも遅いGOODの端が画面内に収まる余白を確保します。エディターの自動プレビューは入力補正0msで表示します。長押しの終端で指を離すタイミングも、この判定範囲を使用します。

入力時は同レーンの未判定ノーツから、範囲内で誤差が最小のものを選びます。同時押しは見た目の連結線と同じ、異なるレーンの始点が1ms以内のノーツを1組とします。各ノーツの入力は個別に判定しますが、得点は組全体の成功が確定してからまとめて加算します。1つでもMISS・シークによるスキップがあれば、その組の得点は0です。長押しを含む組は、その終端の成功まで加点を保留します。判定表示とコンボは各ノーツの結果を使用し、二重加点はしません。PERFECT・GREAT・GOODはすべてコンボを継続し、MISSで解除します。範囲外の空打ちは得点・コンボを変更しません。判定窓と得点は`src/engine.ts`の`WINDOWS`と`POINTS`で変更できます。

長押しは帯状に表示します。始点を判定窓内で押し、終点が判定ラインに来たところで指を離します。始点と終端に同じPERFECT/GREAT/GOOD/MISSの範囲を使用し、両者のうち悪い判定で**1ノーツ分だけ**得点・コンボを確定します。始点では「HOLD」と表示し、まだ加点しません。終端の±160msを超える早離し、終端から160msを過ぎても押したままの場合はMISS・0点となり、再取得できません。終点到達だけでは自動成功にしません。終点が過ぎた短い長押しを後から始めてもMISSです。押したままリスタートしても新しい長押しの始点は自動取得しません。スコアはプレイ中・リザルト・チュートリアルともカンマ区切りで表示します（例：1,000）。

一時停止・バッファリング・時刻更新待ちでは長押しの経過・判定を止めます。停止中に離した場合は再開前に押し直してください。再生中のフォーカス消失や入力キャンセルは指を離した扱いです。シーク時は保持中の長押しをスキップして、得点・MISSを追加しません。

異なるレーンの始点が1ms以内なら同時押しとして◇と連結線で示します。2本は各レーンで独立して得点・コンボを判定します。タップ同士・長押し同士・タップと長押しの組み合わせに対応します。押しっぱなしや同じキーのリピートで追加得点は入りません。同じレーンをキーと指で同時に保持した場合は、最後の入力源を離した時に解除します。フォーカス中のレーンボタンはSpace/Enterでも保持できます。

16分音符が重ならないように、ノーツの初期形状を薄くし、密度に合わせてゲームの厚さとタイムラインの幅を上限調整します。発光も弱くしています。さらにサイズスライダーで調整でき、エディターの初期表示幅は4秒です。小さい画面の密な譜面では、落下時間を短くする・タイムラインの表示幅を2秒にすることで間隔を広げられます。

- `requestAnimationFrame`の各フレームと各入力で`player.getCurrentTime()`を参照し、値が更新されるまでの短い間隔を`performance.now()`で補間します。YouTubeから同じ時刻が返る間もノーツを滑らかに描画します。描画・入力判定・自動MISSは同じ補間時刻を使用し、オフセットも同じ基準で適用します。
- 新しい動画時刻が届くたびに補間を照合し、小さい誤差は速度を緩やかに調整して補正します。YouTubeの再生速度も反映します。動画時刻を離れて独立に進行させません。
- API時刻の更新が途絶えた場合、補間は最大0.5秒間で止め、「更新待ち」を表示して入力・MISS処理を停止します。更新の回復時には再同期し、飛ばしたノーツをスキップします。補間・補正の定数は`src/sync.ts`の`CLOCK_LIMITS`で管理します。
- PLAYINGで時刻更新が有効な間だけMISS処理・入力判定を進めます。一時停止・バッファリング時は補間を止め、再開時に動画時刻へ再同期します。
- 再生中の前回の有効な動画時刻から予測した位置に対して約400msを超える時刻飛び、約60msを超える後退や停止中のシークを検出します。前方シークで飛ばしたノーツは「スキップ」として扱い、MISSや得点を追加しません。コンボは解除します。
- 後方シークは判定・スコアをリセットし、新しい位置より前のノーツをスキップします。バックグラウンドから復帰して時刻が飛んだ場合も大量MISSを避けます。
- リスタートのシーク完了まで入力・MISS処理を保留します。
- 全ノーツを判定またはスキップするとリザルトを表示します。動画は停止しません。得点率は判定済みノーツだけを分母にし、スキップ数を別途表示します。

## ブラウザでの管理者ログイン・編集・公開

[Google管理者ログインの初回設定手順](docs/google-admin-setup.md)に沿って、FirebaseのGoogleログイン、Firestoreルール、管理者UIDの登録とGitHubの`FIREBASE_WEB_CONFIG`変数を設定します。初回設定もブラウザで行えます。Googleのパスワードやサービスアカウント鍵はアプリへ保存しません。

通常はサイトの「管理者ログイン」→Googleログイン→編集→「下書きを保存」→確認→「公開する」で完結します。下書きの閲覧・保存・試遊・公開は、検証済みGoogleアカウントかつFirestoreの`admins/{uid}.enabled == true`のユーザーだけが可能です。管理者の登録・権限変更はFirebaseコンソールで行い、クライアントからの自己昇格はルールで拒否します。公開譜面だけが一般ユーザーの取得対象です。

Firestoreの`draftCharts/{songId}`に下書き、`publishedCharts/{songId}`に公開版を保存します。保存時は読み込んだ版と現在の版が一致する場合だけ次の版へ進めます。公開は保存済み下書きと一致する場合だけトランザクションで行い、空の譜面は公開しません。他の管理者の変更を上書きしません。現在開いているゲームは途中で譜面を切り替えず、次回読込から新しい公開版を使います。

未設定時は管理者ログインを無効にして「準備中」と表示します。未ログイン・未登録のユーザーに編集画面や下書きを表示しません。管理者権限の取り消し・ログアウト時には編集画面を閉じます。クラウドのFirestoreとAuthエミュレーターで権限・保存・公開・試遊を検証しています。実Googleログインと実プロジェクトへの接続は、Firebase設定後に確認します。

## 開発者向けのローカル編集

従来のローカル制作ツールも利用できます。一般の管理者がブラウザで編集する場合には以下のコマンドは不要です。ローカル編集で書き出したJSONをファイルとして収録する場合は、リポジトリへの変更・マージ権限を使用します。

```sh
npm ci
npm run dev:admin
```

管理者用サーバーは既定でPC内のループバックアドレスにのみ接続を受け付けます。ターミナルに表示されるURLをPCブラウザで開き、「譜面を編集」へ進んでください。一般向け画面を確認する場合は`npm run dev`、公開成果物を確認する場合は`npm run build`と`npm run preview`を使います。管理者モードで手動ビルドした成果物は`dist-admin/`へ分離され、Pagesへの配信対象に含めません。

1. エディターの「収録譜面を読み込む」、またはJSON/MIDI読込で譜面を準備します。
2. 編集し、「譜面の再生確認」「ゲームで試す」で確認してJSONを書き出します。ブラウザへの下書き保存や試遊だけでは公開サイトは更新されません。
3. 公開するJSONを`src/charts/`へ追加し、`src/bundled-charts.ts`の登録と`src/songs.ts`の`chartId`を更新します。元のMIDIから生成した`smg002.json`は変換テストの基準でもあるため、編集版は別のファイル名・譜面IDで登録します。
4. `npm test`・`npm run build`・`npm run test:public`で検証します。収録内容を変更した場合は譜面に対応するテストの期待値も確認します。
5. 変更をPRで確認して`main`へマージすると、既存のGitHub Actionsが公開用ビルドを配信します。

以前の下書きや試遊データは消去しません。localStorageはホスト名・ポート・ブラウザごとに分かれるため、以前と同じローカルURLで開くか、書き出したJSONを取り込んでください。公開サイトのブラウザからローカル環境への下書きの自動移行は行いません。以前の公開エディターに下書きがある場合は、変更のマージ前にJSONを書き出し、管理者のローカルエディターへ読み込んでください。切り替え後も元のlocalStorageから下書きは削除しません。

## ノーツ・タイミングエディター（管理者専用）

MVの下の「エディターの再生速度」で0.5倍・0.75倍・1倍を選び、低速で打ち込みと再生確認ができます。動画側で対応していない速度は選択できず、切り替え結果は実際の再生速度で表示します。BPMや譜面の秒数は原曲のまま保存し、ゲームは1倍で開始します。入力補正は実時間の遅れを再生速度に合わせて動画の秒数へ換算します。速度変更中の未完了の長押しは破棄し、速度をまたいだ誤った長さの記録を防ぎます。

「タイムラインの操作」を「範囲を選択」にすると、横方向のドラッグで全6レーンの時間範囲を選択できます。PCではShift＋ドラッグでも選べます。タイムライン下の「範囲のコピー・貼り付け・削除」では秒数の指定・表示範囲の選択もできます。対象は始点が開始以上・終了未満のノーツで、長押しは終点まで含めます。範囲の開始より前から続いている長押しは含めません。

範囲をコピーし、貼り付け位置を指定して「ここに貼り付け」で既存のノーツに追加します。先頭の休符・相対的な時刻・レーン・同時押し・長押しの長さを保ち、新しいIDを割り当てます。コピーはこのページ内で保持し、元のノーツを削除しても貼り付け可能です。範囲の削除と貼り付けは、それぞれ1回の「元に戻す」で戻せます。タイムラインにフォーカス中はCtrl/⌘＋C・V、Delete/Backspace、Escで操作できます。数値入力欄では通常のキー操作を優先します。

オンラインでは「管理者ログイン」からGoogleでログインしてエディターを開きます。ローカル制作ツールの場合は管理者用サーバーを起動し、「譜面を編集」から開きます。管理者用サーバー内の`/editor.html?song=super-mommy-girls`が既存曲の編集画面です。公開サイトの`editor.html`は404になり、オンライン編集は本人確認・権限確認後の`admin.html`で行います。

1. **拍を設定**：曲を聴いてBPM（40～300）と拍の基準時刻を合わせます。「現在位置を拍の基準にする」も使用できます。基準は任意の4分音符の拍の位置で、最初のノーツの時刻とは独立しています。
2. **リアルタイム入力**：「打ち込み開始」を押し、MVを再生してS/D/F/J/K/Lまたは6ボタンで打ち込みます。停止・一時停止・バッファリング・時刻更新待ちでは記録しません。動画操作後は入力エリアへフォーカスを戻してください。追加の打ち込みは既存ノーツに重ねます。「打ち込みの種類」で長押しを選ぶと、押した時刻と離した時刻を記録し、離したときに保存します。再生停止・シーク・入力キャンセル・打ち込み停止で未完了の長押しは破棄します。音声・動画自体を録音しません。
3. **クオンタイズ**：「拍にそろえる」で全ノーツまたは選択ノーツを最寄りの拍へ移動します。初期値は**16分音符**。4分・8分にも変更できます。「元の入力時刻からそろえる」をONにするとBPMや基準を変えて元入力からやり直せます。OFFでは現在の編集時刻を使います。長押しは始点・終点の両方をそろえ、同じ位置へ丸められた短い長押しは最低1分割の長さを確保します。
4. **微調整**：タイムラインまたは一覧でノーツを選択し、ドラッグで時刻・レーンを変更します。ドラッグのスナップは切り替え可能。長押しの本体を動かすと長さを保ち、右端のドラッグまたは終点の数値入力で長さを変更できます。「種類」でタップと長押しを相互変換できます。選択後に別レーンを指定して「同じ時刻に同時押しを追加」で2本にできます。表示幅は2/4/8/16/32秒、±10msボタンや0.001秒刻みの数値入力も使えます。タイムラインにフォーカス中は左右キーで10ms、Shift＋左右で1ms移動できます。秒数目盛りのクリックでシークし、「このノーツの1秒前へ」で聞き直せます。「譜面の試聴音」は通過したノーツのクリック音を鳴らします（打ち込み中は鳴らしません）。
5. **エディター内で再生確認**：「譜面の再生確認」で「譜面の最初から」「現在位置から再生」「選択ノーツの少し前から」を選びます。先頭・選択ノーツからの再生は落下時間＋0.5秒前へシークします。MVと同じ補間時刻で6レーンのノーツを描画し、単押しはTAP、長押しは帯とHOLD、同時押しは◇・連結線と複数レーンの反応で表示します。ノーツ音は始点と長押しの終点で鳴り、プレビュー専用の音量・ON/OFFを設定できます。入力用の補正・音の追加遅延は自動再生に加算しません。一時停止後は「現在位置から再生」で続けられ、「終了」でMVも一時停止します。最後のノーツ・長押しの終点から0.35秒後に自動停止します。再生中は打ち込みを無効にし、ノーツの編集・JSON読み込み・自動補正・タブ非表示ではプレビューを停止します。譜面データや元入力時刻、試遊用の保存データを再生で変更しません。
6. **保存・試遊**：オンライン管理画面では「下書きを保存」で保存し、「保存してゲームで試す」で管理者限定の試遊へ移動します。「公開する」を確定するまで一般プレーヤーの譜面は変わりません。ローカル制作ツールではlocalStorageに自動保存し、「ゲームで試す」で試遊用の譜面を更新します。JSONの読み込み・書き出しでバックアップや端末間の移動ができます。

打ち込みエリアの「入力・タップ音のタイミング調整」で共通設定を変更できます。打ち込みは`videoTime - inputOffset / 1000`を保存し、動画先頭より前になる時刻は0秒へ収めます。長押しは始点・終点に同じ補正を適用し、動画先頭で0秒に切り詰める場合を除いて長さを保ちます。補正値を変えたときは未完了の長押しを破棄します。手動の「現在位置にノーツを追加」は表示中の動画位置を使用します。入力補正を変えても既存の譜面データは動かしません。JSONの元入力時刻にも補正済みの値を保存するので、他の端末でさらに補正する必要はありません。ゲームではその端末での入力時刻に補正を適用します。

元の入力位置は薄い輪郭で表示します。入力・移動・削除・クオンタイズ・JSON読込・空の譜面への変更は、直近50操作までUndo/Redoが可能です（Ctrl/Cmd＋Z、Ctrl/Cmd＋Shift＋ZまたはCtrl＋Y）。履歴はページを開いている間だけ保持します。JSONには元入力時刻と長押しの元の終点も含めます。同じレーンで始点や長押し区間が重なった場合は自動削除せず通知します。

対応は選択中の曲のタップ・長押し・同時押しノーツ、最大5,000ノーツ・JSONは1MB・時刻は0～7,200秒です。動画尺を超えるノーツはゲームで処理できないため、実際の動画内に収めてください。YouTubeの時刻補間を入力と表示に共通で使いますが、APIや端末の遅延は残ります。1msで指定できることと、実際の音楽に1msの精度で同期できることは別です。

「収録譜面を読み込む」でリポジトリに収録された譜面を編集へコピーできます。オンラインの公開済み譜面とは異なる場合があります。現在の編集内容の置き換えは「元に戻す」で戻せます。ゲームや選曲画面を開くだけで保存済みの編集内容を書き換えません。

オンラインの下書きは「下書きを保存」でFirestoreへ送信し、登録された管理者間で共有します。ローカル制作ツールの編集データは**曲・ブラウザ・配信元ごと**に保存され、他の端末へ自動送信されません。ローカルの試遊用譜面は「ゲームで試す」で更新した時点のコピーです。保存制限・容量不足時は画面に表示し、JSON書き出しは引き続き利用できます。読み込んだJSONが不正な場合は現在の譜面を保持します。

## 譜面の差し替え・構成

`src/chart.ts`の`generateChart()`が固定パターンの約30秒譜面を生成します。4分・8分を中心に少数の16分・2点同時押し・1拍分の長押しを加え、同レーンの間隔と長押しの終点後の空きは最低300msにしています。BPM・開始時刻が同じなら譜面も同じです。

エディターで「ゲームで試す」を押すと、ブラウザに曲ごとの試遊用の譜面を保存して`game.html?song=曲ID&chart=custom`でゲームを開きます。初期化・リスタートの両方で同じ編集譜面を使用します。ゲームの「設定 → 使用する譜面」で仮譜面に戻せます。

```json
{
  "videoId": "pJDfWpZ7CI4",
  "title": "SUPER MOMMY GIRLS",
  "bpm": 140,
  "startTime": 12,
  "notes": [
    { "id": 1, "time": 12, "lane": 0, "type": "tap" },
    { "id": 2, "time": 12, "lane": 3, "type": "tap" },
    { "id": 3, "time": 13, "endTime": 14, "lane": 2, "type": "hold" }
  ]
}
```

`time`は動画先頭からの絶対秒数、`lane`は0～5、`id`は一意の正整数としてください。任意の`beatOrigin`は拍の基準の絶対秒数、ノーツの任意の`sourceTime`は元の入力時刻です。長押しは`type: "hold"`と必須の`endTime`（始点より30ms以上後）、任意の`sourceEndTime`（元の終点）を持ちます。同時押しは同じ時刻に異なるレーンのノーツを置きます。既存のタップJSONもそのまま使用できます。エディターでは`startTime`を最初のノーツ時刻から計算します。古いJSONも読み込み可能で、`beatOrigin`がなければ`startTime`を基準にします。読み込み時は選択中の曲の動画IDとの一致を確認します。別の曲のJSONを取り込む場合は、先に選曲メニューからその曲のエディターを開いてください。動画ID・曲名・公式リンクは`src/songs.ts`の登録情報を使用します。
