# HEY! RHYTHM!

Hey!Mommy!「SUPER MOMMY GIRLS」の公式YouTube MVと同期する、非公式ファンメイドの6レーンリズムゲーム・プロトタイプです。Vite + Vanilla TypeScript + Canvasで実装し、バックエンド・DB・ログインは使用しません。

動画ID：`pJDfWpZ7CI4` / [公式MV](https://www.youtube.com/watch?v=pJDfWpZ7CI4)

**初期表示の譜面は動作確認用の仮データです。BPM140は楽曲解析の結果ではありません。** 「譜面編集」で手動の譜面を作成できます。 音声・映像のダウンロード、抽出、複製は行いません。

## ローカル起動

Node.js 22.12以上（クラウドでは24.19.0）、npmが必要です。

```sh
cd /workspace/hey-rtm-game # ローカルではクローンしたディレクトリへ移動
npm ci
npm run dev
```

ターミナルに表示される開発サーバーをPCブラウザで開き、**YouTubeプレーヤー内の再生ボタン**を押します。最初のノーツは動画の12秒地点です。自動再生は前提にしていません。PCでは動画を再生・再開すると、プレーヤーにフォーカスがある場合はゲームへ入力先を戻します。S / D / F / J / K / Lで入力してください。動画の別の操作後に反応しない場合はゲーム領域を一度クリックしてください（YouTube iframe内のキーはゲームに届きません）。YouTube側のキーボードショートカットは無効にしています。下部の6ボタンでも入力できます。ボタンは中央が低いV字配置で、左からピンク・黄緑・白・赤・紫・黄色です。ノーツとレーンの発光も同じ色にしています。スマートフォンを同一ネットワーク上の開発サーバーに接続する場合もHTTPで開いてください。

「最初からやり直す」は譜面とスコアを初期化し、開始時刻より落下時間＋0.5秒前へシークして再生を要求します。iPhone等で再生が始まらない場合は、プレーヤー内の再生ボタンを押してください。一時停止・バッファリング中は入力判定を停止し、スコアを保持します。

## ビルド・静的Webサーバーへの設置

```sh
npm run build
npm run preview
```

`dist/` 内の **index.html・editor.html・assets/をまとめて** 既存サーバーへアップロードしてください。`base: './'` のため `/games/hey-rhythm/` などのサブディレクトリにも設置できます。公開ディレクトリのURL末尾は `/` とし、HTTPSで配信してください。Node.jsは公開先に不要です。

- `file://` でHTMLを開かず、HTTP(S)サーバーを使用してください。
- IFrame APIの`origin`は実際の`location.origin`を設定します。Refererを遮断する`no-referrer` / `same-origin`ヘッダーを設定しないでください。HTMLとiframeは`strict-origin-when-cross-origin`を使用しますが、公開サーバーやブラウザ拡張の設定も確認してください。
- CSPを設定する場合、YouTube APIスクリプトの`www.youtube.com`、`s.ytimg.com`、iframeの`www.youtube.com`を許可してください。MVの通信には`i.ytimg.com`と`*.googlevideo.com`も使用されます。必要なローカルのスクリプト・CSSも許可してください。
- YouTube標準のプレーヤーのクリック・タッチ操作を維持します。`disablekb: 1`でプレーヤー側のキーボードショートカットを無効にし、Fでの全画面化やJ/K/Lでの動画操作を防ぎます。動画の上にゲームUIを重ねません。プレーヤーの高さは最低200pxです。
- 埋め込み拒否・通信障害・Referer不足（153等）は画面に表示し、ゲームを停止します。公式動画へのリンクも常に表示します。

## GitHub Pagesでの公開

公開URLは https://tkisland.github.io/hey-rtm-game/ です。

**リポジトリ直下の開発用`index.html`をそのまま配信すると、TypeScriptを実行できず、CSS・Canvas・YouTubeも読み込まれません。公開にはビルド済みの`dist/`を使います。**

`.github/workflows/deploy-pages.yml`が、`main`へのpush時に`npm ci` → `npm test` → `npm run build`を実行し、`dist/`だけをGitHub Pagesへデプロイします。PRではテスト・ビルドを実行し、公開は行いません。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します（「Deploy from a branch」でリポジトリ直下を配信しないでください）。
2. 公開ワークフローを含む変更を`main`へマージします。
3. **Actions → Build and deploy GitHub Pages** の`build`・`deploy`が成功したら、公開URLを再読み込みします。手動の再公開は同ワークフローの **Run workflow** から行えます。

UIがプレーンな文字だけでYouTubeも空欄の場合、配信HTMLに`/src/main.ts`が残っていないか確認してください。正しい公開HTMLは`./assets/…js`と`./assets/…css`を読み込みます。CSS・JSの両方がHTTP 200で取得できることを確認し、古いページが残る場合はキャッシュを消して再読み込みしてください。

## PCのキーボード入力

YouTube iframe内のキーイベントは配信元が異なるため、ゲーム側のキー処理に届きません。公式プレーヤーの`disablekb`設定で動画のキーボードショートカットを無効にし、PCで再生・再開したときにゲームまたはエディターの入力エリアへフォーカスを戻します。設定入力欄などにあるフォーカスは移しません。フォーカス移動ではスクロールせず、タッチ端末では自動移動しません。動画のクリック・タッチによる再生、一時停止、シーク、全画面ボタンは使用できます。

別の動画操作後にキーが反応しない場合は、ゲーム領域・入力エリアを一度クリックしてください。ブラウザ自体のF11やCtrl/Cmd付きショートカットは通常どおりです。

## スマートフォンの操作エリア

操作ボタンは画面下部に固定し、iPhoneのホームインジケーターの余白を確保しています。V字の左右3ボタンをそれぞれの親指で操作できます。各ボタンの直上にPERFECT / GREAT / GOOD / MISSと入力誤差を表示し、同時押しでもレーンごとに判定を表示します。

動画・ノーツ領域の位置と操作エリアの高さからノーツ領域を調整します。ブラウザのアドレスバー開閉で判定ラインが動かないよう、ノーツ領域には安定した小ビューポートの高さ（`svh`）を使います。タッチ入力ではフォーカスを移さず、画面のスクロールも誘発しません。画面回転や動画・設定パネルのサイズ変更には引き続き追従します。画面が小さくてすべて収まらない場合は上部をスクロールできますが、ボタンは表示されたままです。高さ500px以下の横向きタッチ画面では動画を左、ノーツとボタンを右に配置し、操作エリアが動画を覆わないようにします。

## 設定

右上の「設定」で変更し、localStorageに保存します。保存が制限されたブラウザでも、開いているページ内では使用できます。

| 項目 | 初期値 | 範囲・反映 |
| --- | --- | --- |
| ノーツ落下時間 | 2秒 | 1～4秒、0.25秒刻み。小さいほど速い。即時反映 |
| タイミングオフセット | 0ms | −300～＋300ms、10ms刻み。即時反映 |
| 仮BPM | 140 | 80～200、整数。次回リスタートで再生成 |
| 譜面開始時刻 | 12秒 | 0～3600秒、0.1秒刻み。次回リスタートで再生成 |
| タップ音 | ON | ボタン・キー入力で短いクリック音。OFFも保存されます |
| タップ音量 | 70% | 0～100%、5%刻み。0%は消音。設定を保存 |
| デバッグ | OFF | YouTubeの生時刻、補間後のゲーム時刻、補間状態、プレーヤー状態、適用中BPM、オフセット、FPS、直近の有効入力誤差、最後の判定 |

正のオフセットはノーツの到達・判定を動画時刻より遅らせます。内部では`gameTime = videoTime - offset / 1000`を描画と判定の両方に使用します。BPM・開始時刻の未適用変更は画面に案内します。設定パネルは閉じられます。

タップ音は、立ち上がりの鋭いノイズと短い音程を重ねた75msのクリック音です。Web Audio APIで端末内に合成し、生成した6レーン分の音を再利用します。外部音源は読み込みません。同時押しの音量をコンプレッサーとソフトリミッターで抑え、長い余韻を残さない構成です。ユーザー入力時に音声を有効化するため、ページを開いただけでは鳴りません。再生停止中や空打ちでも押した音は鳴りますが、ゲームの判定・スコアは変えません。YouTubeの音声・同期処理も変更しません。端末の音量、Safariの音声制約、Bluetooth遅延によって聞こえ方は変わります。

## 判定と同期

| 判定 | タイミング誤差 | 点数 | コンボ |
| --- | --- | --- | --- |
| PERFECT | ±50ms以内 | 1000 | 継続 |
| GREAT | ±100ms以内 | 700 | 継続 |
| GOOD | ±160ms以内 | 300 | 継続 |
| MISS | 160ms超で自動判定 | 0 | 解除 |

入力時は同レーンの未判定ノーツから、範囲内で誤差が最小のものを選びます。同時押しは各ノーツを独立判定し、二重判定はしません。PERFECT・GREAT・GOODはすべてコンボを継続し、MISSで解除します。範囲外の空打ちは得点・コンボを変更しません。判定窓と得点は`src/engine.ts`の`WINDOWS`と`POINTS`で変更できます。

- `requestAnimationFrame`の各フレームと各入力で`player.getCurrentTime()`を参照し、値が更新されるまでの短い間隔を`performance.now()`で補間します。YouTubeから同じ時刻が返る間もノーツを滑らかに描画します。描画・入力判定・自動MISSは同じ補間時刻を使用し、オフセットも同じ基準で適用します。
- 新しい動画時刻が届くたびに補間を照合し、小さい誤差は速度を緩やかに調整して補正します。YouTubeの再生速度も反映します。動画時刻を離れて独立に進行させません。
- API時刻の更新が途絶えた場合、補間は最大0.5秒間で止め、「更新待ち」を表示して入力・MISS処理を停止します。更新の回復時には再同期し、飛ばしたノーツをスキップします。補間・補正の定数は`src/sync.ts`の`CLOCK_LIMITS`で管理します。
- PLAYINGで時刻更新が有効な間だけMISS処理・入力判定を進めます。一時停止・バッファリング時は補間を止め、再開時に動画時刻へ再同期します。
- 再生中の前回の有効な動画時刻から予測した位置に対して約400msを超える時刻飛び、約60msを超える後退や停止中のシークを検出します。前方シークで飛ばしたノーツは「スキップ」として扱い、MISSや得点を追加しません。コンボは解除します。
- 後方シークは判定・スコアをリセットし、新しい位置より前のノーツをスキップします。バックグラウンドから復帰して時刻が飛んだ場合も大量MISSを避けます。
- リスタートのシーク完了まで入力・MISS処理を保留します。
- 全ノーツを判定またはスキップするとリザルトを表示します。動画は停止しません。得点率は判定済みノーツだけを分母にし、スキップ数を別途表示します。

## ノーツ・タイミングエディター

ゲーム右上の「譜面編集」から開きます。公開時のURLは https://tkisland.github.io/hey-rtm-game/editor.html です。ローカルでは開発サーバーの`/editor.html`を開きます。

1. **拍を設定**：曲を聴いてBPM（40～300）と拍の基準時刻を合わせます。「現在位置を拍の基準にする」も使用できます。基準は任意の4分音符の拍の位置で、最初のノーツの時刻とは独立しています。
2. **リアルタイム入力**：「打ち込み開始」を押し、MVを再生してS/D/F/J/K/Lまたは6ボタンで打ち込みます。停止・一時停止・バッファリング・時刻更新待ちでは記録しません。動画操作後は入力エリアへフォーカスを戻してください。追加の打ち込みは既存ノーツに重ねます。音声・動画自体を録音しません。
3. **クオンタイズ**：「拍にそろえる」で全ノーツまたは選択ノーツを最寄りの拍へ移動します。初期値は**16分音符**。4分・8分にも変更できます。「元の入力時刻からそろえる」をONにするとBPMや基準を変えて元入力からやり直せます。OFFでは現在の編集時刻を使います。
4. **微調整**：タイムラインまたは一覧でノーツを選択し、ドラッグで時刻・レーンを変更します。ドラッグのスナップは切り替え可能。表示幅は2/4/8/16/32秒、±10msボタンや0.001秒刻みの数値入力も使えます。タイムラインにフォーカス中は左右キーで10ms、Shift＋左右で1ms移動できます。秒数目盛りのクリックでシークし、「このノーツの1秒前へ」で聞き直せます。「譜面の試聴音」は通過したノーツのクリック音を鳴らします（打ち込み中は鳴らしません）。
5. **保存・試遊**：編集内容はlocalStorageに自動保存します。「ゲームで試す」で試遊用の譜面を更新してゲームへ移動します。MVを再生して確認し、「譜面編集」へ戻ると編集を続けられます。JSONの読み込み・書き出しでバックアップや端末間の移動ができます。

元の入力位置は薄い輪郭で表示します。入力・移動・削除・クオンタイズ・JSON読込・空の譜面への変更は、直近50操作までUndo/Redoが可能です（Ctrl/Cmd＋Z、Ctrl/Cmd＋Shift＋ZまたはCtrl＋Y）。履歴はページを開いている間だけ保持します。JSONには元入力時刻も含めます。同じレーンの同時ノーツは自動削除せず重なりを通知します。

対応はこの曲のタップノーツのみ、最大5,000ノーツ・JSONは1MB・時刻は0～7,200秒です。動画尺を超えるノーツはゲームで処理できないため、実際の動画内に収めてください。YouTubeの時刻補間を入力と表示に共通で使いますが、APIや端末の遅延は残ります。1msで指定できることと、実際の音楽に1msの精度で同期できることは別です。

編集データは**ブラウザ・配信元ごと**に保存され、リポジトリや他の端末へ自動送信されません。試遊用の譜面も「ゲームで試す」で更新した時点のコピーです。保存制限・容量不足時は画面に表示し、JSON書き出しは引き続き利用できます。読み込んだJSONが不正な場合は現在の譜面を保持します。

## 譜面の差し替え・構成

`src/chart.ts`の`generateChart()`が固定パターンの約30秒譜面を生成します。4分・8分を中心に少数の16分・2点同時押しを加え、同レーンの間隔は最低300msにしています。BPM・開始時刻が同じなら譜面も同じです。

エディターで「ゲームで試す」を押すと、ブラウザに試遊用の譜面を保存して`?chart=custom`でゲームを開きます。初期化・リスタートの両方で同じ編集譜面を使用します。ゲームの「設定 → 使用する譜面」で仮譜面に戻せます。

```json
{
  "videoId": "pJDfWpZ7CI4",
  "title": "SUPER MOMMY GIRLS",
  "bpm": 140,
  "startTime": 12,
  "notes": [
    { "id": 1, "time": 12, "lane": 0, "type": "tap" },
    { "id": 2, "time": 12.429, "lane": 2, "type": "tap" }
  ]
}
```

`time`は動画先頭からの絶対秒数、`lane`は0～5、`id`は一意の正整数としてください。任意の`beatOrigin`は拍の基準の絶対秒数、ノーツの任意の`sourceTime`は元の入力時刻です。エディターでは`startTime`を最初のノーツ時刻から計算します。古いJSONも読み込み可能で、`beatOrigin`がなければ`startTime`を基準にします。現在の動画IDは`VIDEO_ID`で管理しています。別の動画に対応する場合は公式リンクと楽曲表示も更新してください。
