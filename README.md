# HEY! RHYTHM!

Hey!Mommy!「SUPER MOMMY GIRLS」の公式YouTube MVと同期する、非公式ファンメイドの6レーンリズムゲーム・プロトタイプです。Vite + Vanilla TypeScript + Canvasで実装し、バックエンド・DB・ログインは使用しません。

動画ID：`pJDfWpZ7CI4` / [公式MV](https://www.youtube.com/watch?v=pJDfWpZ7CI4)

**譜面は動作確認用の仮データです。BPM140は楽曲解析の結果ではなく、実際の音楽との一致を保証しません。** 音声・映像のダウンロード、抽出、複製は行いません。

## ローカル起動

Node.js 22.12以上（クラウドでは24.19.0）、npmが必要です。

```sh
cd /workspace/hey-rtm-game # ローカルではクローンしたディレクトリへ移動
npm ci
npm run dev
```

ターミナルに表示される開発サーバーをPCブラウザで開き、**YouTubeプレーヤー内の再生ボタン**を押します。最初のノーツは動画の12秒地点です。自動再生は前提にしていません。PCでは動画操作後にゲーム領域を一度クリックしてからS / D / F / J / K / Lで入力してください（YouTube iframe内にフォーカスがある間はキーを受け取れません）。下部の6ボタンでも入力できます。スマートフォンを同一ネットワーク上の開発サーバーに接続する場合もHTTPで開いてください。

「最初からやり直す」は譜面とスコアを初期化し、開始時刻より落下時間＋0.5秒前へシークして再生を要求します。iPhone等で再生が始まらない場合は、プレーヤー内の再生ボタンを押してください。一時停止・バッファリング中は入力判定を停止し、スコアを保持します。

## ビルド・静的Webサーバーへの設置

```sh
npm run build
npm run preview
```

`dist/` 内の **index.htmlとassets/をまとめて** 既存サーバーへアップロードしてください。`base: './'` のため `/games/hey-rhythm/` などのサブディレクトリにも設置できます。公開ディレクトリのURL末尾は `/` とし、HTTPSで配信してください。Node.jsは公開先に不要です。

- `file://` でHTMLを開かず、HTTP(S)サーバーを使用してください。
- IFrame APIの`origin`は実際の`location.origin`を設定します。Refererを遮断する`no-referrer` / `same-origin`ヘッダーを設定しないでください。HTMLとiframeは`strict-origin-when-cross-origin`を使用しますが、公開サーバーやブラウザ拡張の設定も確認してください。
- CSPを設定する場合、YouTube APIスクリプトの`www.youtube.com`、`s.ytimg.com`、iframeの`www.youtube.com`を許可してください。MVの通信には`i.ytimg.com`と`*.googlevideo.com`も使用されます。必要なローカルのスクリプト・CSSも許可してください。
- YouTube標準のプレーヤーと操作機能を維持します。動画の上にゲームUIを重ねません。プレーヤーの高さは最低200pxです。
- 埋め込み拒否・通信障害・Referer不足（153等）は画面に表示し、ゲームを停止します。公式動画へのリンクも常に表示します。

## GitHub Pagesでの公開

公開URLは https://tkisland.github.io/hey-rtm-game/ です。

**リポジトリ直下の開発用`index.html`をそのまま配信すると、TypeScriptを実行できず、CSS・Canvas・YouTubeも読み込まれません。公開にはビルド済みの`dist/`を使います。**

`.github/workflows/deploy-pages.yml`が、`main`へのpush時に`npm ci` → `npm test` → `npm run build`を実行し、`dist/`だけをGitHub Pagesへデプロイします。PRではテスト・ビルドを実行し、公開は行いません。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します（「Deploy from a branch」でリポジトリ直下を配信しないでください）。
2. 公開ワークフローを含む変更を`main`へマージします。
3. **Actions → Build and deploy GitHub Pages** の`build`・`deploy`が成功したら、公開URLを再読み込みします。手動の再公開は同ワークフローの **Run workflow** から行えます。

UIがプレーンな文字だけでYouTubeも空欄の場合、配信HTMLに`/src/main.ts`が残っていないか確認してください。正しい公開HTMLは`./assets/…js`と`./assets/…css`を読み込みます。CSS・JSの両方がHTTP 200で取得できることを確認し、古いページが残る場合はキャッシュを消して再読み込みしてください。

## 設定

右上の「設定」で変更し、localStorageに保存します。保存が制限されたブラウザでも、開いているページ内では使用できます。

| 項目 | 初期値 | 範囲・反映 |
| --- | --- | --- |
| ノーツ落下時間 | 2秒 | 1～4秒、0.25秒刻み。小さいほど速い。即時反映 |
| タイミングオフセット | 0ms | −300～＋300ms、10ms刻み。即時反映 |
| 仮BPM | 140 | 80～200、整数。次回リスタートで再生成 |
| 譜面開始時刻 | 12秒 | 0～3600秒、0.1秒刻み。次回リスタートで再生成 |
| デバッグ | OFF | 動画時刻、状態、適用中BPM、オフセット、FPS、直近の有効入力誤差、最後の判定 |

正のオフセットはノーツの到達・判定を動画時刻より遅らせます。内部では`gameTime = videoTime - offset / 1000`を描画と判定の両方に使用します。BPM・開始時刻の未適用変更は画面に案内します。設定パネルは閉じられます。

## 判定と同期

| 判定 | タイミング誤差 | 点数 | コンボ |
| --- | --- | --- | --- |
| PERFECT | ±50ms以内 | 1000 | 継続 |
| GREAT | ±100ms以内 | 700 | 継続 |
| GOOD | ±160ms以内 | 300 | 解除 |
| MISS | 160ms超で自動判定 | 0 | 解除 |

入力時は同レーンの未判定ノーツから、範囲内で誤差が最小のものを選びます。同時押しは各ノーツを独立判定し、二重判定はしません。範囲外の空打ちは得点・コンボを変更しません。判定窓と得点は`src/engine.ts`の`WINDOWS`と`POINTS`で変更できます。

- `requestAnimationFrame`の各フレームと各入力で`player.getCurrentTime()`を参照します。ゲーム独自の経過時間を積み上げません。
- PLAYING中だけMISS処理・入力判定を進めます。再開時に動画時刻へ再同期します。
- 再生中の約400msを超える時刻飛び、約60msを超える後退や停止中のシークを検出します。前方シークで飛ばしたノーツは「スキップ」として扱い、MISSや得点を追加しません。コンボは解除します。
- 後方シークは判定・スコアをリセットし、新しい位置より前のノーツをスキップします。バックグラウンドから復帰して時刻が飛んだ場合も大量MISSを避けます。
- リスタートのシーク完了まで入力・MISS処理を保留します。
- 全ノーツを判定またはスキップするとリザルトを表示します。動画は停止しません。得点率は判定済みノーツだけを分母にし、スキップ数を別途表示します。

## 譜面の差し替え・構成

`src/chart.ts`の`generateChart()`が固定パターンの約30秒譜面を生成します。4分・8分を中心に少数の16分・2点同時押しを加え、同レーンの間隔は最低300msにしています。BPM・開始時刻が同じなら譜面も同じです。

将来の手動譜面やMIDI変換は、同ファイルの`Chart`インターフェースに合わせたモジュールまたはJSONを用意し、`src/main.ts`の初期化・リスタートで生成譜面の代わりに読み込む構成にできます。

```json
{
  "videoId": "pJDfWpZ7CI4",
  "title": "SUPER MOMMY GIRLS",
  "bpm": 140,
  "startTime": 12,
  "notes": [
    { "id": 1, "time": 12, "lane": 0, "type": "tap" },
    { "id": 2, "time": 12.429, "lane": 2, "type": "tap" }
  ]
}
```

`time`は動画先頭からの絶対秒数、`lane`は0～5、`id`は一意としてください。現在の動画IDは`VIDEO_ID`で管理しています。別の動画に対応する場合は公式リンクと楽曲表示も更新してください。

| ファイル | 役割 |
| --- | --- |
| `src/chart.ts` | 譜面形式と仮譜面生成 |
| `src/engine.ts` | タイミング判定、スコア・コンボ、ノーツ状態 |
| `src/sync.ts` | YouTube時刻監視とシーク検出 |
| `src/youtube.ts` | IFrame API読込、ready/state/error、origin設定 |
| `src/renderer.ts` | 6色レーン・ノーツ・発光のCanvas描画、DPR対応 |
| `src/input.ts` | キーボード、押しっぱなし抑制、マルチタッチ |
| `src/settings.ts` | 設定検証・localStorage |
| `src/main.ts` | 画面、ゲーム進行、設定・リザルトの接続 |
| `src/style.css`, `index.html` | 日本語UI、レスポンシブ表示、Safe Area |
| `tests/` | 判定・譜面・同期とブラウザ操作の回帰テスト |

## 検証

```sh
npm test
npm run test:e2e
```

ブラウザテストはクラウドの`/usr/bin/chromium`を使用します。別の環境では`CHROMIUM_PATH`にChromium実行ファイルのパスを設定してください。テストは5173ポートでViteを起動します。CIでは同ポートを空けて実行してください。

このクラウドで確認した内容：

- TypeScript型チェックとViteの本番ビルド成功。`npm ci`からビルド・テストまでの再セットアップも成功。
- ビルド済み`dist/`を`/games/hey-rhythm/`として静的配信し、JS/CSSの200応答・画面表示・設定操作を確認（YouTube通信はこの検証から除外）。
- ユニットテスト20件成功：判定境界、最近傍選択、二重判定防止、独立同時押し、得点・コンボ、MISS、オフセット、シーク、再生成、仮譜面の密度、同期状態、設定値検証。
- Chromiumブラウザテスト10件成功（PC・モバイル表示の各5件）：キー連打抑制、停止・バッファリング中の判定停止、シーク・リスタート、2指同時タッチ、設定永続化、DPR描画、最低200px動画領域、横方向のはみ出し防止、リザルト、IFrameエラー、動画時刻によるCanvas更新と停止。
- ブラウザテストでは**YouTube IFrame APIをテスト専用アダプターに置き換えています**。これらの成功は実際の動画再生・通信・音楽との同期精度の保証ではありません。本番実装に疑似再生やローカル音源へのフォールバックはありません。

未検証・制限事項：

- **クラウドの実YouTube通信はネットワークプロキシに拒否されました（CONNECT 403）。実MVの表示・再生・動画との同期精度は未検証です。** `www.youtube.com`、`s.ytimg.com`、`i.ytimg.com`、`*.googlevideo.com`の許可設定を下書きに保存しています。環境設定で変更を確認・保存し、公開してください。その後、実通信と再生を再検証する必要があります。
- iPhone Safari・Android Chromeの実機、iOSでの再生開始制約、実機の2指入力と音声遅延は未検証です。Chromiumモバイルエミュレーションは実機検証の代わりになりません。
- YouTube APIの時刻更新粒度や通信、Bluetooth音声遅延により判定にばらつきがあります。±50msの精度を保証しません。オフセットで調整してください。
- 再生中の小さい前方シークは通常の再生進行と区別できない場合があります。
- 動画の埋め込み可否、公開状態、地域・年齢制限はYouTube側に依存します。
- 小さい端末やブラウザのアドレスバー表示中は縦スクロールが必要な場合があります。操作領域のみスクロール・選択を抑制し、動画操作は妨げません。
- 開始時刻は動画尺内、できれば落下時間より後へ設定してください。譜面が動画の終了を超える場合は全ノーツを処理できません。
- 譜面エディタ、MIDIインポート、ランキング、長押し・スライド・フリックは対象外です。

実動画の最終確認は、MVを再生→S/D/F/J/K/Lと2指タップ→一時停止・再開→前方・後方シーク→設定変更→リスタート→リザルトの順に行い、デバッグ時刻と動画時刻、判定誤差を見比べてください。
